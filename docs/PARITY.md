## Recovered combo and Arcade behavior

Zen uses raw fruit identities in slice order, separately from achievement counters (which alias red apples to apples). Same-kind awards take priority; alternating two-kind combos become Checkers; five-fruit full houses and two pairs precede exact three/four-of-a-kind awards; all-different combos require at least five fruits. Generic three-to-six and seven-plus awards are fallback cases. The original `ALPHABETICAL` enum/art exists, but no branch in the recovered classifier selects it, so this reconstruction does not invent an alphabetical rule. Texture variants retain the original ordering and duplicate weights, including the two identical six-fruit entries. Variant selection currently uses the cosmetic RNG rather than consuming the native gameplay RNG.

Run `python tools/recover_combo_tables.py --check` to independently extract all 25 enum names and texture lists from the SHA-256-checked ARMv7 library and compare them against the port and bundled assets. Addresses in these notes use Ghidra's `0x10000` image base.

Arcade blitz now accumulates energy to a cap of 14, activates above 2.9, promotes in 2.5 increments, and awards 5/10/15/20/25/30 points, with the original six badges, localized titles and sounds. Each slice extends the live normalized window by 0.05 (capped at 1), from `FUN_000855c8`; expiry clears the current chain while retaining the round best. The missing native call site leaves the **one increment per finished combo and bomb reset inferred**. Window expiry uses XML `speedLoss=4`; the original wave/global speed factor and meter interpolation are not yet reproduced. Badge placement, persistent display duration and meter presentation are portable approximations.

`poweruplist.xml` supplies the two-second Arcade start interval and `slowClock=0` for both startup and freeze. The start interval delays the round timer/waves; pause freezes it. Freeze pauses the round timer while its seven-second duration and slowed fruit advance; expiry resumes the clock, including the unpowered fraction of a tick. Double-score duration is eight seconds. Original 60-seconds, ice-cover, frozen-clock, x2 and power-meter artwork is displayed. The XML references `arcade_go`, which is absent from the recovered APK, so the last intro phase currently uses original-font “GO!” text. Effect positions, transitions, deferred x2 points, frenzy particles and native dt interpolation remain work; these changes are not a claim of full Arcade parity.

## Persistence and visual effects

Native `scores.txt` now uses `FRUIT_NATIVE 2`: best scores, counters, earned IDs, distinct fact keys and selected blade/background. Version 1 native high scores migrate without losing values. This does not import the original Android save. Lifetime cuts survive abandoning a round; progress flushes on screen changes, every two seconds while dirty, and normal shutdown. WASM flushes changes to IndexedDB.

The original header/string table index mapping loads all 840 English entries directly from bundled STR files. Texts are not rewritten or substituted with invented achievements. Texture names from configuration are normalized to match case-sensitive filesystems.

Blade emitters reference recovered particle templates for sparkles, stars, butterflies, flame/smoke and snow/fog. Rates, textures, velocity ranges, gravity, start/end size and colors come from the original fast particle XML; template life is interpreted as 60 Hz frames. A separate cosmetic RNG avoids changing fruit spawns or critical outcomes. Effects cap at 128 active particles for handhelds. Native spin, cycling, randomized color/size endpoints, mid-color curves, depth and exact world scaling still need reconstruction.

Menus use recovered fruit meshes, rings, title artwork and Sensei. Mode positions now come from `FUN_00044c88`: centered Classic (-70,71), Zen (88,48), Arcade (19,-76), with Classic ring size 135 and Zen/Arcade 114.75 in the 480×320 view. The back bomb uses native (195,-110) and requires slicing. The original Zen rules sign uses the settled draw translation (194,29), with texture dimensions plus one, from `FUN_00044458`. Its entry slide still needs reconstruction. Results retry is the native apple-center model at (-163,-96); quit is a bomb at (163,-96), from `FUN_00047810`. Tapping these fruit does not activate them.

The HUD uses the original normal/silver/red numeric fonts, watermelon icon and cross atlas. Cross placement/scale/angle comes from the three-row native table at `0xc445c`; the placeholder header and “XXX” lives text are removed. Classic, Zen and Arcade results use their respective original fact/dialogue artwork, with readable original-font text and Zen combo awards. Pause uses recovered title/button artwork and shared input rectangles across platforms. The showcase-calibrated layout uses large play/retry controls, centered audio icons and the original lower-right quit_title artwork; timed modes display a gold m:ss clock. The window contact handler consults those same rectangles; stale top-right pause and tap-back capture regions no longer intercept fruit strokes. Music/sound icons control the mixer and persist in the optional `audio` save-v2 line; older saves default to both enabled. UTF-8 strings are decoded to font code points.

Board placement, fruit radii/poses and menu layout remain calibrated portable values. Original world/camera transforms, full menu/result animation, tutorial, fruit splats, blade cut orientation and material shading remain fidelity work. The Swag catalog now uses the showcase's vertical list, separate preview board and slice-to-equip pineapple. Row positions are video-calibrated. The original BACK artwork, animated selection fruit, XML-driven bomb fuses, full-row dimming and scratch dividers are restored. Scroll momentum and slice/regrowth animations are implemented, but their full native timing/poses and entry choreography remain approximations. Dojo's three fruit controls and Sensei/title rectangles are independently recovered from ARMv7. No claim of pixel-identical screenshots is made.

Wave loading now honors the native default `waitForEntities=true` (`FUN_00088e88`); explicit false remains respected. Pending launches finish before the next-wave delay advances, and entity-waiting waves also wait for fruit/pieces to clear. The prior artificial minimum delay and added launch delay are removed. Native processing/entity filtering in `FUN_00085a70` and speed scaling remain incomplete, so this is not exact wave scheduler parity.

## Critical eligibility

`FUN_0002f60c` and the score updater `FUN_0002f6fc` resolve to the same score global (`0x11dd24`); `FUN_000256f8` skips critical evaluation below two points. `FUN_00024030` disables criticals for zero juice alpha, base fruit score at least the critical award, or explicit `noCritical=true`. The port now applies these gates instead of excluding only dragon fruit. `FUN_00085070` defaults the wave modifier to one, `FUN_00088e88` reads per-wave `criticalChance`, and `FUN_0008575c` supplies it to the critical denominator. Zen's recovered waves specify zero. The native denominator also uses a decrementing counter and resets it to chance + chance_inc after a critical. Its initialization/lifetime and global power modifiers remain unresolved; the port still uses the configured base denominator with the recovered wave modifier. This is partial recovery, not exact critical progression.
